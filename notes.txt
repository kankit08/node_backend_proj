JSON Web Token (JWT) is a way to securely share information between a client (frontend) and a server (backend).

In simple terms, JWT helps the server identify and verify a logged-in user without asking them to log in again for every request.

1. Understand with a simple example
Imagine you are building a job portal.
1. A user enters their email and password to log in.
2. The backend verifies the credentials.
3. If the credentials are correct, the backend generates a JWT token.
4. The backend sends that token to the frontend.
5. The frontend stores the token.
6. Whenever the frontend makes another API request, it sends the token.
7. The backend verifies the token and identifies the user.


2. Why do we use JSON Web Token?
- Authentication: To identify whether a user is logged in.
- Authorization: To check whether a user has permission to access a resource.
- Security: The token is digitally signed, so the backend can detect if its contents have been modified.
- Stateless authentication: The server can verify a token without maintaining a traditional server-side session for every user.


// Access & Refresh Token

. During login
Suppose you enter your email and password.

The backend verifies your credentials and generates two tokens:
- Access Token (expires in 15 minutes)
- Refresh Token (expires in 7 days)
Both are sent to your frontend.
2. After 15 minutes
Your Access Token expires.

Now, the backend will not accept your expired Access Token for protected API requests.

But how will the backend know that you are still an authenticated user?

It needs proof that you are allowed to get a new Access Token.

That's why you send the Refresh Token back to the backend.
3. Why does the backend verify it?
Because the backend cannot blindly generate a new Access Token for anyone who asks.

It checks:
- Is the Refresh Token valid?
- Has it expired?
- Has it been revoked?
- Does it belong to a valid user?
If everything is correct, the backend generates a new Access Token.
